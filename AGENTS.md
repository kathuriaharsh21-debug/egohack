# EgoHack standing rules
WHO: I am a solo student in a 24-hour Egocentric Vision Hackathon run for MyTron Labs (mytronlabs.com). It started about 12:30 IST on 31 Oct 2026. Code freeze is ASSUMED 11:30 IST on 1 Nov 2026 (not confirmed; I will tell you). Run `date` before each phase and tell me the hours left.
PROBLEM: PS2 "What is the hand touching?": per hand per frame decide none / portable object / fixed surface; draw a box on the object and name it. Hand-tracking accuracy is 30 of 100 points and is judged frame by frame on demo clips: every hand found, points on the right joints, left/right never swapped, stable through blur, gloves, occlusion and re-entry.
RUBRIC: hand accuracy 30, PS2 results 20, technical approach 15, usefulness to industry 10, innovation 10, efficiency 5, presentation and honesty 10. Ties are broken by hand accuracy.
FRAMING: an auto-annotation pipeline. It pre-labels hand-object interactions with confidence scores, and low-confidence events go to a human review queue. Claim only what we measure.
DATA: data/clips (full-res) and data/clips. Names look like MTL-SGF00106-021 and mytronlabs-000060-006. Do NOT assume factory_001 names or exactly 20 clips. Mandatory demo clips are not known yet; they live in config.yaml under demo_clips.
DATA RULES (breaking them = disqualification): never commit videos, frames or screenshots; gitignore data/, out/, *.mp4, *.avi, *.png, *.jpg, *.pt, *.onnx, *.task, weights/, credentials, .env; never post anything publicly; only PRIVATE Kaggle datasets; API keys only in environment variables; I delete every copy of the data at the end.
OUTPUT FORMATS (pixel coords in the 480p frame, frame = original frame index, t in seconds): hands.jsonl lines {frame,t,hands:[{id,side,bbox,score,kp2d,kp3d,interp,visible}]} (visible=false means predicted, never counted as a detection; empty list when no hands); objects.jsonl; contacts_frames.jsonl; contacts.csv columns clip,t_start,t_end,hand,state,object_name,object_id,confidence (state = none|portable|fixed); tool_usage.csv; review_queue.csv; metrics_hands.json. common/schema.py defines them, common/validate.py checks them.
RULES OF WORK:
1. Work in phases. At the end of each phase STOP and send a PHASE REPORT with headings: Built; How to reproduce (exact commands); Evidence (numbers with sample sizes, easy vs hard split, file paths, 3 specific timestamps for me to look at); What failed or is uncertain; GPU hours used; Hours left; Research findings; Plan for next phase and why; What I must do. Then wait for me to write "approved". Small fixes inside a phase are fine.
2. Ask me before: installing anything above 1 GB, using GPU beyond 3 h in one run, deleting files, changing output formats, using paid services.
3. Before each phase, spend at most 10 minutes checking current official docs for versions, install commands and limits. Never trust memory for version numbers or limits. If you find a better method, propose it with the expected gain, time cost and risk; do not switch without my approval.
4. One command runs everything: python run_pipeline.py --clip <name> (and --all, and --excerpt 20 for the first 20 seconds). Settings in config.yaml, fixed seeds, stages skip if their output exists.
5. Keep PROGRESS.md updated (status, decisions with reasons, numbers, GPU hours). Commit small and often. Keep README.md and SLIDE_NOTES.md updated at the end of every phase.
6. Honesty: never inflate numbers; always give sample sizes; always split easy vs hard frames; always show failures. Keep code simple and commented because I must explain every line to judges. After each phase give a 5-line plain summary and 3 likely judge questions with answers.
7. CUT LIST if behind, in order: SAM 2 masks, Gemini naming, safety warnings, WiLoR on all frames. NEVER cut: stable hand tracking, left/right correctness, the evaluation, the grab/release timeline, the honest failure report.
